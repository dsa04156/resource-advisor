# 우리의 목적 — NAIS 연구기술직-3 실증

**NAIS 연구기술직-3에 맞춰, 연구자가 학습 작업을 요청하면 GPU·NPU 자원을 확인·선택하고 Kubernetes·Slurm으로 실행하며, 운영자가 할당·진행·사용량·결과를 통합 관리하는 환경을 구축한다. 이를 실제 학습 실행과 면접 발표용 캡처로 입증한다.**

이 문서는 후속 구현·실험·발표 자료 작업의 기준이다. 아래 내용은 **목표와 완료 기준**이며, 현재 모두 구현·검증됐다는 선언이 아니다. 사용자의 후속 지시가 있으면 이 기준도 갱신한다.

## 무엇을 보여주려는가

연구자가 장비마다 접속하거나 스케줄러별 명령을 직접 다루지 않고 연구 작업을 제출하고, 운영자는 서로 다른 연산자원을 한 체계에서 관리하는 모습을 보여준다. 실제 모델 학습은 이 운영 체계가 작동한다는 증거다.

직무의 기준은 GPU·이기종 가속기 운영, 자원 배분·공동활용, 스케줄링·쿼터·우선순위, 통합 현황판·사용량 관리, 런타임·네트워크·스토리지 운영이다. 근거는 [NST 공식 직무기술서](https://www.nst.re.kr/www/downloadBbsFile.do?atchmnflNo=11753)의 연구기술직-3 플랫폼 항목이다.

## 완성해야 할 사용자 흐름

1. **연구자가 작업을 요청한다.** 포털·Kubeflow에서 학습 코드·실행환경과 GPU 종류, VRAM, 장치 수, CPU·메모리, 실행시간, 우선순위를 지정한다.
2. **사용할 수 있는 장비를 확인한다.** GPU와 모빌인트를 포함한 NPU 목록에 장치 모델·자원량·가용 상태를 표시한다. 해당 작업에 적합한 후보와 사용할 수 없는 이유를 함께 보여준다.
3. **실행 위치를 선택한다.** Resource Advisor가 작업 호환성, 자원·정책을 확인해 클러스터·노드 실행 계획을 만든다. 여러 장비를 사용하는 작업은 토폴로지·네트워크 조건도 고려하고 선택 근거를 남긴다.
4. **기존 실행 체계에 제출한다.** Kubernetes 경로는 Kueue의 입장·쿼터 정책과 Kubernetes의 배치·장치 할당을 사용한다. Slurm 경로는 Account·QOS·GRES 등 해당 환경의 정책과 자원 할당을 사용한다.
5. **학습과 자원 운영을 함께 확인한다.** 요청한 자원과 실제 할당 장비, 대기 사유, 실행 상태, 학습 로그·지표, 예약·사용량, 결과·실험 이력을 연결한다. Kubeflow는 학습 흐름을, MLflow는 연결된 실험·모델 결과를 관리한다.

## Resource Advisor의 역할

Resource Advisor는 **Kubernetes와 Slurm 위의 공통 자원·작업 관리 계층**이다. 공통 요청을 받아 후보와 실행 계획을 정하고, 어댑터로 각 환경에 제출하며, 상태·결과·사용량을 수집한다. 실제 입장·할당은 각 실행 환경이 판단한다.

Kubernetes에 장치가 리소스로 노출돼 있고 해당 장치용 런타임·작업 코드가 준비돼 있으면, Pod가 그 리소스를 요청해 사용한다. 예를 들어 `nvidia.com/gpu`와 `mobilint.com/npu`가 있다. 별도의 장치 연결 서버를 만드는 일을 이 자원 관리 흐름의 선행 조건으로 두지 않는다.

장비 노출은 임의 모델의 실행 호환성이나 학습 지원을 보장하지 않는다. 지원되는 작업·런타임을 검증해 후보로 제공한다. GPU·NPU 공동 활용 요구는 유지하되, 특정 모델의 내부 계산 분할이나 두 장치의 공동 역전파를 프로젝트 목적 자체로 바꾸지 않는다. 이미 작성한 Qwen3-VL 특징 전송·LoRA 실험 코드는 선택적인 워크로드 구현이며 전체 플랫폼 완성의 증거가 아니다.

## 발표 자료까지의 완료 기준

- GPU·모빌인트 장비 목록, 작업 요청, 적격 후보·제외 이유와 배치 근거를 확인할 수 있다.
- 실제 제출한 작업의 Kubernetes 또는 Slurm 식별자, 할당 장비, 상태가 공통 작업 기록으로 연결된다. 두 경로의 실증 범위는 각각 기록한다.
- 실제 모델 학습의 진행 로그·지표와 결과가 남는다. 모빌인트가 수행한 실제 작업과 역할도 기록한다.
- 여러 장비를 사용한 경우 실제 배치·연결과 토폴로지 판단의 근거를 남긴다. 미측정 네트워크 수치를 만들어 넣지 않는다.
- 발표용 캡처에서 **요청 → 자원 선택 → 대기·할당 → 학습 진행 → 결과·사용량**을 설명할 수 있다. 계획 화면, 과거 기록 재생, 실제 실행 화면을 구분한다.

후속 작업자는 기능 하나의 구현 완료를 위 전체 목적의 완료로 보고하지 않는다. 현재 코드와 실증 근거에서 빠진 연결을 확인하고, 이 흐름을 완성하는 데 필요한 작업부터 진행한다.
