# Full v0.3 completion audit

The objective is the full design, not the subset already implemented. An empty
or indirect evidence cell means incomplete. Synthetic tests cannot satisfy a
hardware acceptance gate. Keep this list open until every required gate has
direct evidence; conditional extensions require an explicit applicability result.

The design fixes M0–M6 as the required delivery and M7 as an optional extension.
R2/R3 activate only for groups meeting their fidelity/source-data conditions.
An unsuccessful qualification must remain an explicit inactive result; it must
not be relaxed to manufacture an applicable group. R1 and S0/S1/S2 remain required.

Rows also retain broader operational risks. HA, off-site object-store recovery,
global fairness, arbitrary-program support and model-registry integration are
not substitutes for the specified lab acceptance tests or newly imposed
completion prerequisites. Conversely, a bounded pass does not close those
production risks. Required project authorization, result ownership, backup/restore
and the specified real-backend failure scenarios still need direct evidence.
See [the milestone map](implementation.md) for the implementation sequence.
