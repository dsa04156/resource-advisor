# 처음 사용하는 Resource Advisor

이 프로젝트는 **내가 쓸 수 있는 계산 자원을 보고, AI 작업을 실행하고,
결과와 사용 시간을 확인하는 도구**입니다. 첫 사용은 아래 순서면 됩니다.

## 1. 화면 열기

설정된 API 주소 뒤에 `/console`을 붙여 접속합니다. 현재 연구실 설정에서는
토큰 입력 없이 기본 프로젝트로 바로 연결됩니다. 인증을 사용하는 다른 설치
환경에서만 프로젝트 토큰을 입력합니다. 관리자용 장비·실행환경 등록은 인증이 필요합니다.

## 2. 자원 보기

**실행 현황**에서 CPU·메모리 막대와 GPU/NPU 목록을 봅니다.

| 표시 | 쉽게 읽는 법 |
|---|---|
| CPU·메모리 실측 | 최근 수집한 사용량·여유 메모리 |
| 예약 여유 | 이미 요청된 자원을 뺀 값. 즉시 실행을 보장하지는 않음 |
| 공유 슬롯 | GPU를 나눠 쓰기 위한 논리 단위. 물리 GPU 개수와 다름 |
| 미측정·확인 불가 | 현재 사용할 수 있는 측정값이 없음. 사용률 0%라는 뜻이 아님 |

기본적으로 15초마다 갱신하며, **지금 갱신**으로 직접 조회할 수도 있습니다.

## 3. GPU 작업 실행하기

1. 왼쪽 **작업 제출** 또는 실행 현황의 **＋ 새 작업 제출**을 엽니다.
2. **작업 템플릿**에서 실행할 작업을 선택합니다. Orin 데모는 `slurm-orin-cnn-api-v1`입니다.
3. **실행 장비 · 백엔드**에서 후보를 선택합니다. Orin 데모는 Slurm의 `orin` 후보입니다.
4. 요청 자원과 제한 시간을 확인하고 **작업 제출**을 한 번 누릅니다. 새 작업이 접수되고 실행 현황으로 이동합니다.
5. 해당 작업의 **실행 상세 · 결과 · MLflow**를 펼쳐 결과를 확인합니다.

`작업 제출`은 선택한 템플릿의 조건으로 한 번 실행하고 기록을 남기는 동작입니다.
다른 장비로 자동 이주하거나 자동으로 최적 구성을 찾는 버튼은 아닙니다.
버튼이 비활성화돼 있으면 표시된 이유를 확인하세요. `CAPABILITY_STALE`은
실행 환경 확인이 만료됐다는 뜻으로, 관리자의 재확인이 필요합니다.
작업 목록이 길면 아래 **이전/다음**으로 이동합니다.
입력 중 선택값이 사라지지 않도록 폼을 사용하면 자동 갱신이 꺼집니다.
제출 후 필요하면 **15초 자동 갱신**을 다시 켜세요.

### 새 작업 템플릿 등록

**작업 제출 → 새 작업 템플릿 등록**을 펼치고 `WorkloadSpec` JSON 파일을 선택합니다.
파일의 `project_ref`는 화면 위의 프로젝트와 같아야 합니다. **작업 템플릿 등록**은
명세만 저장하며, 이후 장비를 골라 **작업 제출**을 눌러야 실제 계산이 시작됩니다.

명세에는 `ref`, `project_ref`, `identity`, `candidates`, `baseline_candidate_ref`,
`quality`, `execution` 등이 들어갑니다. 완전한 생성 예제는
[build_cnn_study.py](../examples/build_cnn_study.py), 정확한 필드 정의는
[WorkloadSpec](../src/resource_advisor/contracts.py)을 참고하세요.
실행 후보는 관리자가 등록한 런타임과 장비 검증을 참조해야 하며, 등록만으로
실행 자격이 생기지는 않습니다. 임의의 Python 파일·모델 파일 업로드 실행은
현재 지원하지 않습니다.

## 4. 상태와 취소 이해하기

| 화면 상태 | 의미 |
|---|---|
| 접수됨·제출 중 | 서버가 작업을 확인하고 스케줄러에 전달 중 |
| 대기 | 작업이 접수됐지만 아직 자원을 받지 못함 |
| 실행 중 | 스케줄러가 실행 중으로 보고함. 준비 단계도 포함 |
| 결과 수집 | 실행 출력의 형식·식별자·내용을 확인 중 |
| 완료 | 결과가 정상 수집됨. 별도의 **품질 통과/미통과**도 함께 확인 |
| 실패·결과 검증 실패 | 상세에 표시된 원인 확인 |
| 취소 요청·백엔드 종료 확인 중 | 취소 요청은 전달됐고 실제 종료를 기다리는 중 |
| 취소 | 백엔드 종료 확인이 끝남 |

멈추려면 실행 중인 작업의 **작업 취소**를 누릅니다. 종료된 작업에는 버튼이 없습니다.
이미 완료된 작업과 취소 요청이 겹치면 완료 결과가 유지될 수 있습니다.

## 5. 결과 숫자 읽기

실측 시간은 모델의 측정 구간, 자원 할당 시간은 GPU 등을 예약한 전체 시간입니다.
예를 들어 [실제 Orin 데모](slurm-api-results.md)는 10회 추론 합계 약 **11ms**,
한 번의 추론 중앙값 약 **1.08ms**, GPU 예약은 **72초**였습니다.
예약 시간에는 실행 전 환경 검증과 준비가 포함됩니다.
**대기 · 할당 이력**에는 실패·취소한 작업의 예약 시간도 남습니다.

추천을 사용하려면 **가속기 호환성 → 추천 받기**를 누릅니다.
**추천 근거 · 실제 결과**에서 후보·자원량과 **근거와 실제 결과 보기**를 확인한 뒤
**이 구성 승인 → 승인한 구성 실행** 순서로 진행합니다. 추천 받기와 승인만으로는
계산 작업이 시작되지 않습니다. 근거가 부족하면 추천을 보류하며, 만료된 추천은
다시 받아야 합니다. [실장비 추천 예시](approved-gpu-demo.md)도 참고할 수 있습니다.

## 구성요소는 각각 무슨 일을 하나요?

| 구성요소 | 역할 |
|---|---|
| 이 웹 화면 + FastAPI | 사용자의 요청을 받고 작업 상태·결과를 보여줌 |
| Kubernetes / Kueue | 컨테이너 실행과 실행 전 큐·쿼터·우선순위 관리 |
| KubeEdge | 기존 Kubernetes 환경의 엣지 장비 실행 기반 |
| Slurm | 별도 계산 서버의 작업 대기열·자원 할당·실행 관리 |
| Kubeflow Pipelines | 데이터 준비 → 실행 → 평가처럼 여러 단계를 묶음 |
| PostgreSQL | 작업 상태·실행 이력·사용량을 저장 |
| MLflow / S3 | 실험 조건·측정값 / 결과 파일을 저장 |
| Prometheus | CPU·메모리 등 수집된 인프라 측정값을 제공 |
| Advisor | 비교 가능한 실행 이력으로 다음 구성을 추천하고 근거를 남김 |

처음에는 **자원 보기 → 한 번 실행 → 결과 보기 → 사용량 보기**만 따라 해도
각 도구가 어디서 쓰이는지 이해할 수 있습니다.
